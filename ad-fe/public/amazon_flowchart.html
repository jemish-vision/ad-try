Fee & Pricing Structure

The following information is based on Amazon's official documentation and announcements for the Selling Partner API (SP-API) and Amazon Ads API.

1. Amazon Selling Partner API (SP-API)

Private / First-Party Integration Internal Business Use

Private (first-party) applications built solely for a seller's own business are not currently subject to separate SP-API subscription or usage fees.

  • You only pay your normal Amazon selling fees (commissions, FBA, referral fees, etc.).
  • Rate Limits: Although no API fees currently apply, all SP-API operations remain subject to Amazon's documented rate limits and usage plans.
  • Private-to-Public App Migration: Under the cancelled proposal, no conversion or upgrade fees exist for transferring a private app to public. However, the migration itself requires standard Amazon developer registration and public app authorization workflows.
🔗 Official Amazon Fee Announcement

Public / Third-Party SaaS Integration SaaS / Appstore

Amazon previously announced a proposed pricing model for third-party/public applications serving multiple sellers.

  • Subscription: Proposed 1,400 USD/year SP-API subscription fee.
  • Usage: Proposed usage-based charges for very high GET call volume (above the free tier).
  • Status: Amazon announced that the proposed SP-API pricing program was postponed and was later officially cancelled. As of the latest official Amazon announcement, the proposed SP-API annual and usage fees are not being implemented.
🔗 Main SP-API Fee Announcement (1,400 USD + Usage) 🔗 Follow-up: Delayed Implementation / Advanced Tier

2. Amazon Ads API

Amazon Advertising API Fees Standard

Amazon does not charge any separate licensing or subscription fee for access to the Amazon Ads API. Developers pay only the normal advertising costs incurred by campaigns and any applicable Amazon selling account fees.

  • Ad Spend & Account Fees: Any normal Amazon seller account fees (if applicable) and advertising campaign spend still apply.
“There are no additional fees from Amazon Ads to use the API. The only fees include standard account fees to sell on Amazon, as well as the campaign costs for using Amazon Ads advertising products.”

Best Practices

  • Headers: Respect the x-amzn-RateLimit-Limit response header when available.
  • Backoff: Implement exponential backoff after HTTP 429 Too Many Requests responses.
  • Polling: Avoid continuously polling report or feed status endpoints.
  • Batching: Batch operations where supported to reduce API calls.
  • Monitoring: Monitor application metrics and retry behavior to prevent throttling.

STREAM CONNECTIVITY & SUBSCRIPTION LIFECYCLE

  • 1. AWS Infrastructure Connectivity Setup & Permissions: Configure standard/FIFO SQS Queues in your AWS Account. You must attach an SQS Queue Policy granting message-delivery permissions (specifically sqs:SendMessage) to the Amazon Ads Service Principal.
  • 2. User Subscription Selection (UI): Open the Manage Subscriptions Dialog (SubscriptionModal.js) to select dataset feeds (Sponsored Products/Brands/Display Traffic & Conversion data, Budget metrics).
  • 3. Backend API Authentication & Mapping (ARN_MAP): Trigger backend routes (/api/manageSubscribeAMS) to fetch configuration settings and Ads auth tokens. The system dynamically maps the Amazon Ads profile URL to retrieve the pre-defined target SQS ARN (sqsArn), SQS Queue URL (sqsQueueUrl), and AWS region name via amsArn.js.
  • 4. Lifecycle Synchronization & Confirmation Email: Compare selection with existing database configurations. New feeds trigger Amazon Stream API POST /streams/subscriptions and create local records with status PENDING_CONFIRMATION. Amazon then pushes a SubscriptionConfirmation message to the SQS queue, which the Consumer Service catches to email a confirmation URL to the administrator (using buildSqsConfirmationEmail.js). Once the URL is clicked to verify the SNS-to-SQS handle, the status updates to ACTIVE. Unselected feeds trigger PUT /streams/subscriptions/{subscriptionId} to archive, updating local databases to ARCHIVED.

Developer Onboarding & Learning Roadmap

A comprehensive guide for incoming developers to understand the project structure, Amazon Ads and SP-API architecture, local environment configuration, and core tasks to get completely up to speed.

Core Codebase Structure

  • frontend (R-AdvertiseIQ)
    React client with styled custom UI components, Ag-Grid tables, routing, context stores, and dynamic custom column managers.
  • backend (Node-AdvertiseIQ)
    Express API-server handling endpoints, authentication, and core database queries.
  • background workers
    Independent processes handling cron jobs, data sync pipelines, and heavy report parser queues.
  • database
    MongoDB models (mongoose schemas) as the central persistent layer for synced metrics, logs, and rules.

Key Amazon Concepts

  • LWA (Login With Amazon)
    OAuth 2.0 flow to secure seller authorization, yielding short-lived access tokens and long-lived refresh tokens.
  • SP-API (Selling Partner API)
    Retrieves catalog, listings, inventory, orders, reports, and financial data through REST APIs. Event-driven updates can also be received through the SP-API Notifications API integrated with AWS messaging services.
  • Amazon Ads API
    Manages campaign lifecycle, budgets, placements, keywords, bids, and pulls bulk metrics.
  • Amazon Marketing Stream
    Hourly push-based near real-time performance streaming to AWS SQS queues.

Core Tools & Utilities

  • AG-Grid Customizations
    Shared table grids use AgTable, managing column order, pinning, dynamic column updates, cell renders, and inline-edit popups.
  • Stream Processing
    To prevent RAM issues when parsing massive FBA/orders report datasets, the system streams file buffers via stream-chain and stream-json.
  • Dynamic Mongo Queries
    Frontend filter metrics are converted into MongoDB query filters using backend parser helper functions (like buildMongoQuery).
  • Caching & Session Store
    Uses Redis key-value caching (redis.service.js) to store active profile metadata, session information, permissions, and other frequently accessed application data.
